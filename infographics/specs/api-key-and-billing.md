# What an API Key Is — and How Billing Works

**Slug:** `api-key-and-billing`

**Status:** Approved for course use

**Placement:** Lesson 02-04 and cost routing

**Source:** New course visual. Provider-dependent wording is deliberate; no rate, currency, or allowance is stated.

**Construction mode:** Built-in image generation, followed by deterministic resize and WebP export.

## Production prompt

```text
Create a 1200×675 infographic titled “What an API Key Is — and How Billing Works”. Subtitle: “A secret credential identifies software requests.”

Flow: “Your server” → “Request + secret API key” → “Provider API” → “Response”.

SECRET API KEY:
“A secret credential for software”
“Identifies the project or account making the request”
“Does not belong in browser code, screenshots or Git”

USAGE AND BILLING:
“Usage may be measured by input, output, calls or tool use”
“Prices and limits differ by model and provider”
“Set budgets and alerts in the provider account”

Notes:
“A chat plan may not include API usage. Check the provider’s billing page.”
“If a secret key is exposed, rotate it immediately.”

Use no example key, logo, price, currency, or provider promise.
```

## Accessibility text

**Alt text:** A server sends a request and secret API key to a provider API and receives a response. Two cards explain that a secret API key identifies software requests and must stay out of browser code, screenshots, and Git, while usage measurements, prices, and limits depend on the provider.

**Caption:** A secret API key identifies software requests; API usage may be billed separately from a chat plan.
